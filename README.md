在集成实战系统中发现代码复现失败了.
### 失败原因:
- 没有办法评价第一阶段训练的结果. 码本虽然可以进行动作归类.但是依然过于模糊.没有框架来评估码本的好坏.选择码本的版本变得非常困惑.
- 第二阶段虽然可以训练出选择器, 但是由于使用t0窗口的数据来进行选择.在验证集上几乎完全无关联.猜测是因子数据和码本之间关联太弱了.暂时不知道怎么更好的改良.
- 没有尝试第三阶段.
- 由于我训练数据使用的国内商品期货的数据. 
    - 0.由于数据少, 我采用了10秒作为精度的数据
    - 1.训练数据太少. 70的分片大小最终只生成了2万笔分片, 商品期货的交易时间比较短.导致数据不足.
    - 2.商品期货的(燃料油)数据密度不足. 缺少订单信息明细成交信息. 挂单的明细信息导致订单簿只是快照很多因子失效.
    - 3.训练集和测试集有数据漂移的情况. 波动率完全不一样.
- 之前开发的版本之所以是成功的,因为在第二阶段将整个分片用来作为输入进行了验证.看上去收益爆棚,实际上是错的.
- 在过fineft的论文后我发现, 当前架构中缺少了一个防守策略.因为selector必然会选择一个码本.这种方式可能会导致选择了一个未必适合的码本虽然第三阶段可以进行微调,但是一旦码本错了,微调的意义不大.
